# 范围定义（Scope）

> 这份文档的唯一作用：**在你想加功能的时候，能拿出证据说不。**

范围一旦模糊，工具集合就会变成功能堆。所以这里写的「不做」，和「做」同等重要。

---

## 一、产品的一句话边界

```text
Sparrow = 一组小工具 + 一个全局热键入口 + 一套统一的上下文与结果动作。
其中每个工具都是一个独立插件。
```

超出这句话的东西，默认不做。

---

## 二、判断标准：三问过滤器

每加一个工具或功能，问三句：

```text
1. 它服务「一次热键闭环」吗？
2. 我自己每周会用它吗？
3. 它让产品变快，还是只是变大？
```

**三句里有一句答不上，就进 P2 或直接砍。** 不接受「以后可能有人需要」。

---

## 三、本期（P0）做什么

P0 = 第一个能自我验证的闭环。**只有 3 个工具。**

理由：这 3 个工具分别覆盖「纯文本 / 结构化文本 / 图像→文本」三种上下文形态，能压测上下文模型的全部主路径。

| # | 工具 | ID | 为什么是它 |
|---|---|---|---|
| 1 | 剪贴板历史 | `sparrow.clipboard.history` | 全部工具共用剪贴板，它同时验证存储、搜索、固定 |
| 2 | JSON 格式化 | `sparrow.json.format` | 最典型的「文本进、文本出」，最短路径跑通全链路 |
| 3 | 截图 OCR | `sparrow.ocr.region` | 唯一需要截图 + 原生库 + 独立进程的工具，验证最重的一条路 |

配套的壳能力（不算工具）：

```text
全局热键 · 命令面板 · 托盘常驻 · 单实例 · 设置读写 · 历史落库 · 日志
```

## 四、明确不做（本期）

### 4.1 永久不做

| 不做 | 原因 |
|---|---|
| 云同步 / 账号体系 | 违反「本地优先」，且需要服务端 |
| 插件市场 / 第三方插件分发 | 做工具，不做平台；插件隔离成本 > 收益 |
| 工作流编排 / 节点连线 | 是另一个产品，不是工具集合 |
| 脚本运行时（用户写 JS/Python） | 沙箱、安全、调试成本全部转嫁给自己 |
| 内嵌浏览器 | 不解决任何桌面摩擦 |

> AI 模型接入是例外：只做本地/云端 provider 配置，不做账号体系、云同步、模型市场；云端调用必须由用户显式配置。

### 4.2 本期不做，但保留在 catalog

| 不做 | 推到 |
|---|---|
| SVG 描摹 / 导出 | M2（它是第二个产品，不是第一个的功能） |
| AI 翻译 / 总结 / 视觉重绘 | M1.3（可选基础设施；不配模型时工具提示「先配置模型」，不影响其他工具） |
| 文件批量重命名 / 哈希 | M2 |
| 图片格式转换 / 缩放 | M2 |
| Text 正则提取、去重排序 | M1 |
| Dev 工具（Base64 / 时间戳 / JWT） | M1（成本极低，用来验证「加工具不改壳」） |
| JSON 转 C# / JSONPath / Diff | M1 / M2 |
| OCR 表格识别 | P2 |
| 开机自启 | M1（第一周就会被要） |

完整清单见 [`tool-catalog.md`](tool-catalog.md)，那里有阶段标记，这里不重复。

## 五、范围守卫

### 5.1 「顺手加一个」的拒绝模板

> 「这个工具本身不难，但它的输入形态是 `<新形态>`，会给上下文模型加第 7 种分支。收益是每周 0.2 次使用，成本是永久维护一条路径。进 P2。」

### 5.2 什么情况下允许扩大范围

只有一种情况：**P0 的三个工具已经连续用了一周，且每天都用。**

在那之前，所有「我觉得还缺 XX」都记录进 catalog 的候选区，不进入开发。

### 5.3 每个里程碑必须有「出口条件」

里程碑不是「做完了这些功能」，而是「能验证的假设成立了」。见 [`roadmap.md`](roadmap.md)。

## 六、成功标准

### 工程验收（可自动化，见 release-checklist.md）

```text
dotnet build 零警告
Core / Modules 单测全绿
冷启动 < 2.5s，二次唤起 < 150ms
三个工具的完整闭环可跑通
```

### 产品验证（人工，一周后结论）

> **连续 7 天，每天主动唤起 ≥ 3 次，且没有一次觉得「还不如手动」。**

达不到 → **不加功能**，回去磨闭环：热键响应、面板搜索排序、结果复制路径。

这是 Sparrow 唯一的增长指标。
