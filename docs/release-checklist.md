# 发布验收清单（Release Checklist）

> 分三类，**不要混**：
> - **工程验收**：可自动化，每次提交都跑
> - **手工验收**：每次发版前跑
> - **产品验证**：一周后的人工结论，不是发版门槛

---

## 一、工程验收（CI 必须全绿）

### 1.1 构建

```text
[ ] dotnet build 零 warning（TreatWarningsAsErrors 已开）
[ ] dotnet build 零 error
[ ] Sdk / 插件 TargetFramework = net10.0；宿主 = net10.0-windows10.0.19041.0
[ ] global.json 锁定 SDK 10.0.103
[ ] CI（.github/workflows/ci.yml）Release 构建 + 测试全绿
```

### 1.2 依赖规则

```text
[ ] Sparrow.Plugin.Sdk 的 ProjectReference 数量 = 0
[ ] plugins/* 只引用 Sparrow.Plugin.Sdk（OCR worker 例外）
[ ] plugins/* 的 csproj 不含 Avalonia.*
[ ] Sparrow.Plugin.Sdk 不引用 Avalonia.*
[ ] ViewModel 不引用 Avalonia.Controls.*
```

### 1.3 插件边界（最重要的一组）

```text
[ ] 删掉 plugins/ 下任一插件目录 → 宿主能启动，面板无该工具，无报错
[ ] 插件产物目录里没有 Sparrow.Plugin.Sdk.dll
[ ] 宿主源码不出现具体工具 ID（PluginBoundaryTests 通过）
[ ] 宿主源码不散落插件参数键（PluginBoundaryTests 通过）
[ ] 每个插件目录名 == plugin.json 的 id
[ ] plugin.json 的 tools 与该插件实际的 Descriptor.Id 一致
[ ] ALC 为 isCollectible: true
[ ] 禁用插件后，ALC 被回收（弱引用已死）
```

检查 SDK 泄漏：

```bash
dir plugins/*/bin/Release/net10.0/Sparrow.Plugin.Sdk.dll
# 必须无输出
```

### 1.4 版本钉死

```text
[ ] SkiaSharp = 3.119.4
[ ] Svg.Skia = 5.1.1
[ ] Avalonia = 12.1.6
[ ] （如接入）Avalonia.AvaloniaEdit = 12.0.0
[ ] 没有间接引入 SkiaSharp 4.x（dotnet list package --include-transitive 检查）
```

第 5 项最容易漏。检查命令：

```bash
dotnet list package --include-transitive | findstr SkiaSharp
```

出现 `4.x` 就是有人升级了 `Svg.Skia` 或手动加了 SkiaSharp。

### 1.5 测试

```text
[ ] Sdk / App 单测全绿
[ ] 已接入测试的插件单测全绿（当前 13 个插件）
[ ] 快照测试全绿
[ ] 无跳过的测试（Skip 必须写原因）
[ ] 当前基线：910 用例（2026-11-28）
```

### 1.6 性能

| 指标 | 阈值 | 怎么测 |
|---|---|---|
| 冷启动 | < 2.5s | 5 次取中位；实测 946ms（2026-11-21） |
| 二次唤起 | < 150ms | 按键到可见 |
| 命令搜索 | < 50ms | 13 个工具 |
| 文本工具 | < 100ms | JSON 格式化 1MB |
| 常驻内存（主进程） | < 150MB | 无 OCR 运行；实测 120MB（见 `docs/performance.md`） |
| 安装包 | < 80MB | 不含 OCR；自包含 + 本地推理实测 68.9MB（原 60MB 目标已不现实） |

### 1.7 安全

```text
[ ] 日志中无完整剪贴板内容
[ ] 日志中无密钥
[ ] 日志中无 AI 请求原文
[ ] SVG 输出已过白名单清洗（无 script / on* / foreignObject / 外链）
[ ] 设置的 secrets.bin 权限受限（仅当前用户可读）
[ ] 局域网互传默认监听行为已在隐私说明中披露
[ ] 互传 PIN / 接收目录 / 关闭开关可用
```

## 二、手工验收（每次发版）

### 2.1 冷启动与常驻

```text
[ ] 双击图标 → 托盘出现，无窗口弹出
[ ] 右键托盘 → 菜单完整
[ ] 杀进程后重新打开 → 无残留、无重复图标
[ ] 开机自启开启后重启 → 自动进托盘
```

### 2.2 热键

```text
[ ] Ctrl+Alt+S 唤起面板，输入框自动聚焦
[ ] 再按一次 → 面板隐藏
[ ] Esc → 隐藏
[ ] 被其他软件占用 → 有明确提示，且不崩
[ ] 切换显示器后仍能正确唤起（出现在鼠标所在屏）
[ ] 混合 DPI（100% + 150%）下文字不模糊、位置不偏
[ ] 开启「接管 Win+V」→ Win+V 打开 Sparrow 剪贴板；关闭后 Win+V 恢复系统行为
[ ] 托盘勾选「禁用快捷键」→ 所有全局热键失效；取消后恢复
[ ] 托盘勾选「全屏游戏时禁用快捷键」→ 独占全屏 D3D 游戏内热键暂停，退出后恢复
```

### 2.3 命令面板

```text
[ ] 输入 "json" → 首项是 JSON 格式化
[ ] 输入中文 "格式化" → 能搜到
[ ] ↑↓ 循环选择，不越界
[ ] Enter 执行，结果卡片出现
[ ] 结果耗时显示正确
[ ] 空查询显示最近使用 + 固定项
[ ] 连续搜索 20 次不卡顿
```

### 2.4 三个闭环

```text
闭环 A：剪贴板 -------------------------------------------------
[ ] 复制一段文字 → 500ms 内进历史
[ ] 面板搜到该条 → 回车 → 内容回到剪贴板
[ ] 固定一条 → 重启后仍在
[ ] 搜索历史关键词 → 命中
[ ] 删除一条记录 → 列表和库都消失

闭环 B：JSON ---------------------------------------------------
[ ] 复制 JSON → 面板搜 json → 格式化结果正确
[ ] 切换「压缩」→ 输出无空白
[ ] 输入非法 JSON → 提示行列号，不报堆栈
[ ] 1MB JSON → 100ms 内完成
[ ] 结果可复制，粘贴出来是格式化后的内容

闭环 C：OCR ----------------------------------------------------
[ ] Ctrl+Alt+C → 屏幕变暗，可框选
[ ] 框选文字区域 → 识别结果出现
[ ] 结果可复制
[ ] 识别完 60s 后子进程退出（任务管理器确认）
[ ] 主进程内存回落到 150MB 以内
[ ] 全屏截图（4K）不崩
[ ] 「识别类型」选「表格 · Markdown」→ 本地 SLANet 能出表格（没配视觉模型也不报「需要视觉模型」）
```

### 2.5 边界

```text
[ ] 复制 500MB 文件到剪贴板 → 程序不卡不崩，历史里标记「过大」
[ ] 复制图片 → 历史里显示缩略图
[ ] 空剪贴板按热键 → 面板正常打开，不报错
[ ] 断网 → 非 AI 工具全部正常
[ ] 磁盘写满 → 有明确错误，不静默失败
[ ] 工具执行中被 Esc / 取消按钮中断 → 无残留进度条
```

### 2.6 插件管理

```text
[ ] 设置页能看到所有插件的列表（名称 / 版本 / 状态）
[ ] 禁用 1 个插件 → 面板里立刻消失，重启后仍禁用
[ ] 启用回来 → 面板里恢复，参数与插件设置保留（工具参数在 `parameters.json`，插件设置在 `settings.json` 的 `plugins` 节点）
[ ] 删掉一个插件目录 → 重启正常，无报错，其他插件不受影响
[ ] 故意改坏某插件的 plugin.json → 该插件被跳过并提示「清单无效」，其他插件正常
[ ] 连续禁用/启用 10 次 → 任务管理器内存无持续增长
[ ] 插件登记的 `Host.OnDispose` 清理回调 → 禁用/卸载后执行，内存不持续增长
[ ] 把插件目录的 SDK dll 手动放回去 → 日志出现「loaded but no ITool found」（验证铁律 1 的告警有效）
```

最后一项不是找茬，是**验证故障可诊断**——最怕的是插件静默不加载且没有任何提示。

**当前未实现，不作为发版门槛：**

- Faulted（连续失败 3 次）状态与灰显重试。

**能力校验：**

```text
[ ] 未配置 AI 时，`sparrow.svg.prompt` 在面板 / 工作区灰显，并提示「AI 模型（未配置）」
[ ] 配置 AI 后重新打开面板 → 该工具恢复可用
[ ] 不可用工具可点开查看原因，但执行按钮置灰
```

### 2.7 文件搜索

```text
[ ] 首次点击「重建索引」→ 弹出管理员确认，完成后能搜到文件
[ ] Ctrl+Alt+F 唤起搜索框，输入文件名 → 结果出现
[ ] 双击 Ctrl 也能唤起（设置里可关）
[ ] 设置里取消某个盘 → 重启后该盘结果消失
[ ] 安装索引服务 → 新建 / 删除文件后，搜索结果能实时变化
[ ] 卸载索引服务 → 搜索回退到静态 .idx，不崩
[ ] 搜索面板不阻塞 UI，连续输入不卡顿
```

### 2.8 局域网互传

```text
[ ] 两台同网段设备能互相发现（或手动输入 IP:端口）
[ ] 默认（免确认关闭）每次上传弹确认框，显示发送方与文件列表
[ ] 打开「免确认接收」→ 直接写入接收目录
[ ] 设置接收 PIN 后，发送方必须输入相同 PIN
[ ] 接收目录改为自定义路径 → 文件落到新路径
[ ] 关闭「开启互传」→ 端口不再监听，重启后仍关闭
[ ] 传输大文件时进度正常，取消后无残留临时文件
```

## 四、产品验证（不是发版门槛）

**发版后一周，人工回答一个问题：**

> 你有没有连续 7 天、每天主动唤起 ≥ 3 次，且没有一次觉得「还不如手动」？

| 结果 | 结论 | 下一步 |
|---|---|---|
| 是 | 闭环成立 | 进入下一里程碑 |
| 否，但每天会用 1–2 次 | 方向对，速度不够 | **不加功能**，优化唤起 / 搜索 / 复制路径 |
| 否，几乎不用 | 假设不成立 | 停下来，找真实场景，不要继续堆工具 |

**这一条永远不进 CI。** 它靠人诚实，不靠脚本。

## 五、发版决策表

| 情况 | 是否发版 |
|---|---|
| 工程验收全绿 + 手工验收全绿 | 发 |
| 有 1 项手工验收未过，但非核心闭环 | 发，记 issue |
| 核心闭环（A/B/C 任一）未过 | **不发** |
| 版本钉死被改动 | **不发**，先回滚 |
| 日志/密钥泄露 | **不发**，这是安全事件 |
