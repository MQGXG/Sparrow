# 界面规格（UI Spec）

> 界面只为「工具集合」服务：**同一套骨架，装不同的工具。** 工具不拥有界面，只贡献参数和结果。

---

## 一、三种入口，一套骨架

| 入口 | 唤出方式 | 用途 | 尺寸 |
|---|---|---|---|
| **命令面板** | `Ctrl + Alt + S` | 主力。搜工具 → 立即执行 | 640 × 420，居中偏上 |
| **截图识别** | `Ctrl + Alt + C` | 选区 → 动作栏（识别 / 复制 / 保存 / 固定） | 全屏选区 |
| **工作区窗口** | 面板里选「打开工作区」 | 需要看大结果、调参数 | 1100 × 720 |
| **托盘菜单** | 右键托盘图标 | 最近工具、设置、退出 | 系统菜单 |

**M0 只做命令面板 + 托盘。** 工作区窗口 M1 再补。

理由：命令面板能验证 90% 的体验假设，工作区是「看结果更舒服」的增强，不是闭环前提。

## 二、命令面板（M0 唯一的主界面）

```text
┌──────────────────────────────────────────────────────┐
│  🔍  搜索工具、粘贴内容后回车…                        │  ← 输入框，自动聚焦
├──────────────────────────────────────────────────────┤
│  ▸ JSON 格式化                        格式化 · json   │  ← 选中项，Enter 执行
│    Base64 编解码                       开发 · 编码    │
│    截图识别文字                          OCR · 截图    │
│    文本变形                             文本          │
├──────────────────────────────────────────────────────┤
│  ↑↓ 选择   Tab 补全   Enter 执行   Esc 关闭           │  ← 键盘提示，常驻
└──────────────────────────────────────────────────────┘
```

### 2.1 交互规则（这些是产品的核心，不是细节）

| 行为 | 规则 |
|---|---|
| **唤起** | 记起上次位置；若焦点窗口在另一块屏，则出现在那块屏（按该屏 DPI 缩放） |
| **输入即筛选** | 每次按键即时过滤，延迟 ≤ 50ms，不显示 loading |
| **命中高亮** | 名称和描述里的匹配片段标琥珀色 + 半粗，大小写不敏感；只高亮，不改文本 |
| **排序** | `匹配度 × 权重 × 最近使用` 三者加权，不按字母序 |
| **空查询** | 显示最近使用的 5 个 + 固定工具，不是全部工具列表 |
| **粘贴后回车** | 输入框里的内容不是工具名时，按「输入形态」匹配工具（文本 → 文本类工具） |
| **Esc** | 有输入时清空；无输入时隐藏到托盘 |
| **失焦** | 隐藏到托盘（可设置关闭） |
| **执行中** | 面板不关，显示进度；完成后面板内直接出结果卡片 |

### 2.2 结果卡片（面板内，M0 起始）

```text
┌──────────────────────────────────────────────────────┐
│  JSON 格式化                                  12 ms  │
├──────────────────────────────────────────────────────┤
│  {                                                   │
│    "name": "sparrow",                                │
│    "version": 1                                      │
│  }                                                   │
├──────────────────────────────────────────────────────┤
│  [复制]  [保存]  [固定]  [发送到…]                    │
└──────────────────────────────────────────────────────┘
```

- 文本结果限高 6 行，超出滚动，不自动撑高面板。
- 图片结果限高 240px。
- 结果标题右侧显示「N 字 · M 行」；「正在识别…」这类占位不统计。
- 错误用红色左边框 + 一行说明，不带堆栈（堆栈进日志）。

## 三、工作区窗口（工具台）

工作区的交互模型是**双态**：默认是「工具墙」（启动器），点工具卡片进入「工具台」（单工具工作区）。

```text
┌─────────────────────────────────────────────────────────────┐
│  ◆ 麻雀 · 工具台          [🔍 搜索工具…]              [设置] │
├─────────────────────────────────────────────────────────────┤
│  工具    最近使用                              12  TOOLS    │  ← 共享切换行（墙/最近页都可见）
│  [全部 12] [文本 4] [数据 3] [图像 2] …      ← 分类 chips   │
│                                                             │
│  ▍ 图像 · 2                                    ← 分组标题   │
│  ┌ 取景框卡片网格……                                          │
│  │ [icon卡]  [icon卡]  [icon卡]  [icon卡]                     │
│  └ 取景框角标：hover 张开变琥珀                              │
│                                                             │
│  台态（点卡片进入，整宽）                                     │
│    ‹ 返回  [icon] 名称·chip   [复制][执行▶]                  │
│    参数（行内） / 输入 / 结果（主角）                          │
└─────────────────────────────────────────────────────────────┘
```

**三区**：共享切换行（工具 / 最近使用，工具台时隐藏） / 工具墙·最近页·工具台三态 / 顶栏（品牌+搜索）。动作按钮（复制/保存/执行）在工具台头部右侧，紧贴当前工具，不放状态栏。

| 设计点 | 规则 |
|---|---|
| 共享切换行 | 「工具 / 最近使用 / 剪贴板」不在任何 ScrollViewer 内；任何页面都可见，任何状态都能切回工具墙（导航不卡死） |
| 工具墙 | 按分类分组的卡片网格（236px）；组标题 = 琥珀刻度 + 分类名 + 数量 + 折叠箭头 |
| 分组折叠 | 点 chip：过滤列表（和之前一致）；点组标题：手动折叠/展开（记忆在会话内）；搜索词非空时强制全展开 |
| 最近使用 | 只在「最近使用」页展示；工具墙不再放最近使用大卡或最近执行条 |
| 剪贴板页 | 左：搜索 + 类型 chips（全部/文本/链接/图片/文件/收藏）+ 标签 chips + 列表（缩略图、摘要、自动/手动标签、时间、收藏星）；右：详情（全文 / 大图 / 文件路径）+ 复制 / 删除 + 标签增删；清空需二次确认 |
| 剪贴板分类 | 自动标签：链接 / 邮箱 / 颜色 / JSON / 路径；图片与文件按类型；手动标签参与搜索与筛选；收藏不受条数上限清理 |
| 分类导航 | 顶部横排 chips；「全部」是虚拟分类；选中 chip 亮琥珀、计数变琥珀等宽数字；显示名可用 `categories.json` 的 `labels` 覆盖（见下） |
| 空态 | 工具墙无命中时，中央显示取景框内的大号麻雀标记 + 说明文案 |
| 工具台 | 占满整宽；面包屑返回（Esc 同效）+ 工具头（图标/名称/分类 chip/描述 + 右侧动作：复制/保存/执行）+ 参数行 + 输入 + 结果 |
| 参数 | 行内水平排开（WrapPanel），不占整栏；开关型的 label 跟在开关后；记住上次选择（`parameters.json`），截图 OCR 也用这份值 |
| 输入来源 | 文本工具可直接编辑/粘贴；图片集工具（OCR）用拖入、`添加图片…`、`粘贴剪贴板` 收集 1..N 张图，工具页显示缩略图条（点缩略图看大图）；单图工具优先用拖入的图片，其次剪贴板；拖入文本文件自动填入；文件工具（哈希等）用多文件清单，拖入多个文件时自动切到文件工具 |
| 结果 | 占满剩余高度；错误用红色左边条 + 一行人话 |
| 工具卡片 | hover 时底色提亮 + 琥珀描边；右下「打开 →」平时隐藏，hover 才浮现（`TextBlock.hint`） |
| 最近执行条 | 无（已删除，与「最近使用」页执行记录重复）；历史完整保留在「最近使用」页 |
| 状态栏 | 无（已移除）。执行状态由执行按钮自身表达：执行中置灰，有进度时显示「正在识别 b.png（2/5）」，否则「执行中…」 |
| 顶栏搜索 | 即时过滤工具墙（名称/描述/分类），不清空分类选中；在最近页输入时自动回工具墙 |

Windows 原生标题栏通过 DWM 切成深色（`WindowChrome`），避免深色窗口顶着一整条白条。

### 3.0 分类显示名自定义（`categories.json`）

位置：`%LOCALAPPDATA%\Sparrow\categories.json`，启动时读取；文件不存在 = 用内置显示名。

```json
{
  "labels": {
    "json": "JSON 处理",
    "dev": "编码工具",
    "ai": "AI 工具"
  }
}
```

| 规则 | 说明 |
|---|---|
| 只覆盖显示名 | 插件的 `ToolDescriptor.Category` 键不动，分类过滤逻辑不受影响 |
| 未配置的分类 | 使用宿主内置名（`ToolCategories.cs`）；未知分类原样显示 |
| 空键 / 空值 | 忽略，不会出现空白分类名 |
| 文件损坏 | 记一条警告日志，回退内置名，不影响启动 |
| 删除文件 | 回到内置默认，无需改代码 |


### 3.1 渲染器映射

| Payload | 渲染器 |
|---|---|
| `TextPayload` | 等宽文本 + 语法高亮（AvaloniaEdit） |
| `SvgPayload` | ✅ Svg.Skia 5.1.1 渲染 PNG；预览 / 源码切换；宿主先做安全清洗 |
| `ImagePayload` | 图片查看（缩放 / 适应宽度） |
| `FileSetPayload` | ✅ 文件清单（数量 + 逐行路径）；「打开所在位置」仍待结果动作契约 |
| `TablePayload` | ✅ 等宽对齐文本（表头 + 分隔线 + 行）；列按最大显示宽度补齐，中文按两列宽 |

**工具不能自定义渲染器。** 需要新的展示形态 = 新的 Payload 类型 = 一次架构变更，要慎重。

## 四、视觉 token

唯一来源：`src/Sparrow.App/Styles/Theme.axaml`。界面里不再写散落的十六进制颜色。

### 4.0 风格母题：「取景框 HUD」

界面的一切装饰都从「精密仪器的取景框」这一个母题里长出来，不引入第二套装饰语言：

| 签名元素 | 规则 |
|---|---|
| **取景框角标** | 卡片 1px 细描边 + 四角 L 形 2px 角标（`Path.frame`），常驻半透明琥珀、贴内角；hover 变实、向角张开到贴边（margin 3→0）并提亮底色。这是 Sparrow 的签名交互 |
| **工具卡片** | 236×136；图标 40px 方角座（CornerRadius 2）+ 琥珀线稿图标（`Button.tool-card Path.icon`）；右下「打开 →」hover 浮现 |
| **点阵图纸底纹** | 32px 一格的极淡灰蓝点（`DotGridBrush`，Assets/dot-grid.png）铺在窗口最底层；小浮层（命令面板）压暗到 60% |
| **窗角斜线** | 顶右 / 底左各一组 45° 细斜线（琥珀 8% 透明度，`IsHitTestVisible=False`），只做空气感，不许放在内容附近 |
| **大数字读出** | 数量、结果统计用等宽 20px（`.stat`）+ 全大写英文小标签（`TOOLS`），像仪表读数 |
| **HUD tab** | 一级导航是文字 + 底部 2px 琥珀刻度线（`Button.hud-tab`），无底色无描边 |
| **分类 chip** | 方角（2px）、细描边、低存在感（`Button.hud-chip`），选中才亮琥珀 |

禁止：把角标/斜线用在浮层按钮、错误卡片等「非仪器」语义上；斜线透明度 >10%。

```text

描边        #2B3543   常态
描边强      #3D4959   浮层、hover 边界

主色悬浮    #F0B463
主色按下    #C98C3A
主色底      #251D12   选中项底色
主色描边    #5C4A26
主色淡选    #20E5A44C  截图选区 / 文本选区（12% 透明琥珀）

文本        #E9EEF6

渐变        只允许三处：窗口底 / 面板·浮层底 / 主按钮，
            明度差压在 ±5% 以内（WindowBg / Surface / Panel / Accent 渐变）
圆角        14（浮层） / 12（面板、窗口） / 8（按钮、输入框） / 4（chip、kbd）
间距        4 / 8 / 12 / 16 / 24（8dp 节奏，不出现 22/18/14/9 等任意值）

            17 title / 20 brand —— Theme.axaml 里的 .title/.subtitle/.body/
            .caption/.micro 类，界面里不写中间值，不用 10px（Windows 缩放下发虚）
数据数字    计数、时间、尺寸等数字统一 .num（等宽字体），强化工具气质

```

规则：

1. **只有一个强调色**。不再引入青/绿/紫做装饰；语义色只用于错误。
2. **主按钮整屏最多一个**（`Button.accent`），其余用描边按钮或 `Button.ghost`。
3. **层级靠背景和阴影，不靠描边堆叠**。浮层用 `BoxShadow`，卡片用 `Border.panel`。
4. **系统强调色已覆盖**：列表选中、开关、下拉高亮都从 `SystemAccentColor` 派生，
   不会回到 Fluent 默认的紫/蓝。
5. 分类、版本号等弱信息统一用 `TextMutedBrush` + 小字号，不抢主信息。

**只支持深色主题（M1）**。浅色主题 M2 再做——它需要一整套新 token，不是换个背景色。

### 4.1 图标

分类 → 线性图标，映射在 `src/Sparrow.App/Converters/IconGeometryConverter.cs`。

```text
画布      24×24，使用时缩到 18px（面板）/ 15px（工作区）
线宽      1.5，圆头圆角，只用 stroke 不填充
颜色      常态 TextSecondary；选中变 Accent
映射      json → {}    dev → <>    ocr → 扫描框+文本行
          text → 文本行    format → 层叠方块    clipboard → 板夹+勾

```

图标是视觉标识，不属于业务数据，所以**不放进 ViewModel**；ViewModel 只提供
插件声明的 `Category`。XAML 用 `{x:Static IconGeometryConverter.Instance}` 引用转换器——
放在 `Styles.Resources` 里的 `StaticResource` 在 DataTemplate 里解析不到。

## 五、状态设计

每个工具都可能处于 5 种状态，界面必须都覆盖：

| 状态 | 表现 | 现状 |
|---|---|---|
| **空态**（无输入） | 面板空结果显示「执行后结果显示在这里」；搜索无命中显示「没有匹配的工具」 | ✅ |
| **就绪**（有输入、未执行） | 输入已就位，参数显示默认值，动作条只有「执行」 | ✅ |
| **执行中** | 顶部 2px 琥珀色不定进度条，执行按钮置灰并改为「执行中…」；重复 Enter 被挡住 | ✅ |
| **成功** | 结果卡片 + 复制动作；耗时显示在标题右侧 | ✅ |
| **失败** | 红色卡片 + 一句人话（`Detail` 只进日志） | ✅ |
| **不可用** | 工具置灰，hover 显示原因 | ⬜ 未实现（当前没有需要平台能力的工具） |

「执行中」这道闸是功能性的：OCR 一次 2–3 秒，用户会重复按 Enter，
没有拦截就会起两个 worker 进程、结果互相覆盖。
回归测试见 `tests/Sparrow.Tests/PaletteViewModelTests.cs` 的 `执行中再次回车_不会重复执行`。

「不可用」这一态最容易被忽略，但它是插件化工具集合的必需品。等第一个需要网络/平台的工具进来时补。

### 6.1 中文输入法下的 Enter（实测踩到的坑）

中文输入法激活时，字母键和 Enter 都会被 Avalonia 标记为 `Key.ImeProcessed`：

```text
输入 j s o n   → TextBox 仍是空的（"json" 在 IME 组合缓冲区）
第一次 Enter   → IME 把 "json" 上屏 → 搜索框更新 → 列表过滤
第二次 Enter   → Key.Enter → 执行工具
```

**宿主规则：见到 `Key.ImeProcessed` 直接放行，绝不抢。**

如果抢了第一次 Enter，会发生：先执行工具 → 随后上屏触发搜索刷新 → 结果被清空。
用户看到的现象是"按了回车没反应"（其实执行过，只是结果被覆盖了）。

代价是中文输入法下要按两次 Enter。这是可接受的：第一次 Enter 本来就在做「确认输入」。
英文输入法或无 IME 时一次即可。

回归测试见 `tests/Sparrow.Tests/PaletteWindowTests.cs` 的 `ImeProcessed的Enter_不执行工具也不复制`。

### 6.2 为什么快捷键走隧道阶段

`TextBox` 会把 `Enter` 标成已处理、把 `Ctrl+C` 交给自己的复制命令。
冒泡阶段（包括 `handledEventsToo`）都拿不到，所以窗口在 `RoutingStrategies.Tunnel` 上先处理。

### 6.3 截图动作栏（Ctrl+Alt+C）

松开鼠标后不直接截图：选区进入可编辑态，可整体拖动，也可拖 8 个控制点缩放（拖角对角固定，拖边对边固定）；选区上方实时显示 `X, Y  宽 × 高`（物理像素）。点动作时才真正抓图。

动作栏在选区下方，贴底时翻到上方；选区移动/缩放时动作栏跟随。

识别文字**不跳结果面板**：行框直接叠在选区上，点哪行复制哪行。旧插件只返回纯文本时，才回退到面板展示。

```text
选区 → Enter → 行框叠加（N 行）
     → 点行：复制该行
     → Ctrl+C：复制全文
     → R：重新识别
     → Esc：先清 overlay，再按一次取消
```

| 键 | 行为 |
|---|---|
| `Enter` / `R` | 就地识别；已有结果时 `R` 重新识别、`Enter` 复制全文 |
| `Ctrl + C` | 有结果时复制全文 |
| `C` | 复制图片（PNG 转 CF_DIB 写剪贴板） |
| `S` | 保存为 PNG（默认 `Sparrow-yyyyMMdd-HHmmss.png`） |
| `P` | 固定到屏幕（置顶贴图，可拖动，滚轮缩放 0.5–2.0；右上角常驻半透明 ✕，悬停变亮，点击/双击/`Esc` 关闭） |
| `G` | 进入滚动截图（见 6.4） |
| `Esc` | 有 overlay 时先清除；没有时取消 |

**动作栏没有文本输入，`Key.ImeProcessed` 按物理键还原后直接消费**，
不像命令面板那样放行给输入法——否则中文输入法下字母快捷键会全部失效。

截图时窗口只把 `Opacity` 置 0（不是 `Hide()`），否则动作栏会跟着消失。

### 6.4 滚动截图

```text
选区 → G → 选区窗口关闭，选区外出现提示条
     → 用户用滚轮滚页面（提示条不抢焦点，ShowActivated=false）
     → 点「完成」停止 → 拼接 → 预览窗口（识别 / 复制 / 保存 / 固定）
     → 点「取消」丢弃
```

拼接完全在宿主完成（`ScrollStitcher`），插件仍然只收到一张 `ImageInput`，
所以这条功能没有改 SDK 契约。

算法：用上一帧最后 T 行（`clamp(帧高/4, 40, 160)`）做模板，在下一帧里找它出现的位置，
把模板之后的行追加进结果。行哈希匹配，避免逐像素比较跟不上 240ms 的抓帧节奏。

边界：

- 找不到重叠（滚动过快、页面跳变）→ 自动停止，保留已拼部分
- 纯色页面（行哈希全相同）→ 判定为「没有滚动」，不会误拼
- 长图上限 20000px
- 不支持横向滚动、动态加载导致的布局跳动

实测：1200×1000 选区滚动 14 次，拼出 1200×3100，无重复、无断层。

## 七、托盘

```text
图标：琥珀圆角底 + 深色麻雀剪影（Assets/sparrow.ico，托盘用 32px PNG）
      exe 图标、任务栏、窗口标题栏共用同一套资源
左键单击：唤出命令面板
右键菜单：
  ├ 搜索工具…            Ctrl+Alt+S
  ├ 截图识别…            Ctrl+Alt+C
  ├ ────────────
  ├ 最近结果（5 条）
  ├ 设置
  ├ 开机自启   ☑
  ├ ────────────
  └ 退出
```

图标三态（待机 / 忙碌 / 错误）**尚未实现**：目前异常状态只改 tooltip 文本
（`TrayService.SetStatus`），不换图标。等有长时间任务需要反映到托盘时再补。

Windows 11 默认把新图标收进「∧」溢出区，这是系统行为，程序无法强制展开。
需要常驻可见时，用户在任务栏设置里打开「显示所有系统托盘图标」，或把图标拖出溢出区。

**实现注意**：Avalonia 12 的 `TrayIcon` 构造后不会自动挂到应用上，
必须放进 `Application` 的 `TrayIcons` 集合（`TrayIcon.SetIcons`）才会创建原生图标。
少了这一步的表现是：进程正常、日志正常，但托盘里什么都没有。
`TrayServiceTests` 守着这条。

**首次运行**：应用默认只启动到托盘，用户容易以为没启动。
检测到 `settings.json` 不存在时，自动展示一次命令面板；之后恢复纯托盘行为。
带 `--workspace` 启动时打开工作区，不再弹面板。

## 八、插件管理（设置里的一个分段）

工具都是插件，所以「管理工具」= 「管理插件」。只有一页，不做花活。

设置页内部用顶部分段：**插件 / 模型 / 热键 / 通用 / 关于**（HUD tab：文字 + 琥珀刻度线）。同一时间只显示一个分段，切换不丢失未保存的输入；返回仍然回工作区，不新开窗口。

### 8.1 工具热键（`toolHotkeys`）

除搜索 / 截图两条内置热键外，任意工具可以挂全局热键，按下直接执行、不打开面板：

```json
"toolHotkeys": { "sparrow.window.pin": "Ctrl+Alt+P" }
```

| 规则 | 说明 |
|---|---|
| 注册时机 | 启动时按配置注册；工具被禁用 / 卸载时执行会提示「工具不存在」 |
| 格式错误 | 只跳过该条并记日志，不影响启动 |
| 设置页编辑 | 设置 → 热键 → 工具热键：点输入框后**直接按组合键**录制（隧道层拦截，Backspace/Delete 清空）；单一字母/数字必须带修饰键；格式错误 / 与其他热键重复会拒绝保存并提示 |
| 托盘入口 | 配置了热键的工具直接作为**一级菜单项**（如「窗口置顶… Ctrl+Alt+P」）；名称只读插件清单，启动时零插件加载 |
| 托盘菜单自定义 | `settings.json` 的 `trayMenu` 定义顺序/分隔线/动作/工具项：`action` = palette / capture / workspace / exit，`tool` = 工具 ID；空数组 = 内置默认；非法条目跳过并记日志 |
| 结果展示 | 执行完成后用命令面板展示结果，并写入执行历史；取消（如窗口拾取按 Esc）不弹错误 |

排版遵循「取景框 HUD」母题（§4.0）：

| 组件 | 规则 |
|---|---|
| 分区头 | `Border.hud-tick`（2px 琥珀刻度条）+ 分区名（12 SemiBold）+ 右侧等宽计数或 `// EN` 小标 |
| 设置行 | 左：34px 琥珀方块座里的线性图标（`Border.hud-icon`）；中：标题（13 SemiBold）+ 说明（11 muted）；右：控件 |
| 分隔 | 行与行之间用发丝线（`Border.hud-line`），不再给每行套卡片描边 |
| 关于 | 身份卡排版：琥珀方块 Logo + `SPARROW //` mono 小标 + 大标题 + 右侧「版本/平台/状态」三组仪表读数 |
| 状态反馈 | 应用内 toast：右上角轻提示，4 秒自动消失，点击可关闭，不抢焦点；用于设置保存结果、热键注册失败、托盘/热键执行结果等 |

```text
┌─────────────────────────────────────────────────────────────┐
│ 设置 › 插件                                                  │
├─────────────────────────────────────────────────────────────┤
│  名称              版本     工具数   状态      操作          │
│  JSON 格式化       1.0.0     1       ● 启用    [禁用] [目录]  │
│  文件哈希          0.1.0     1       ● 启用    [禁用] [目录]  │
│  截图识别          1.0.0     2       ● 启用    [禁用] [目录]  │
│  图片描摹          0.9.0     1       ○ 禁用    [启用] [目录]  │
│  某第三方插件      0.1.0     1       ⚠ 异常    [重试] [目录]  │
├─────────────────────────────────────────────────────────────┤
│  [打开插件目录]   [重新扫描]                                  │
└─────────────────────────────────────────────────────────────┘
```

| 设计点 | 规则 |
|---|---|
| 不做「在线安装」 | `scope.md` 已明确不做插件市场。只能「打开目录」手动放 |
| 状态只有 4 种 | 启用 / 禁用 / 异常 / 不可用（能力不满足） |
| 异常可重试 | 不要求重启应用，重新加载该插件即可 |
| 显示工具数 | 提醒用户「一个插件可能提供多个工具」（OCR 就是 2 个） |
| 不显示内部路径 | 「打开目录」按钮代替展示路径，减少误操作 |
| 不提供「设置」入口 | 工具的参数在工具自己的参数区，不在插件管理页 |

**异常状态必须给原因**，一行小字：

```text
⚠ 异常   清单无效：plugin.json 第 4 行缺少 "entryAssembly"
⚠ 异常   版本不兼容：需要 SDK 2.x，当前 1.0
```

没有原因的灰显等于让用户猜，这比不显示更糟。

### 8.1 设置 › 通用

| 项 | 规则 |
|---|---|
| 开机自启 | 只启动到托盘 |
| 历史最多保留 | 50–5000 条，默认 500；改完立即按新上限剪一次 |
| 历史保留天数 | 0 = 不按天数清理；默认 0，避免升级后误删旧记录 |

## 九、反模式（明确不做）

| 不做 | 原因 |
|---|---|
| 每个工具一个独立窗口 | 工具集合退化成「一堆小软件」 |
| 工具自定义 UI 布局 | 界面不可预测，加工具成本爆炸 |
| 动画 > 150ms | 高频工具，动画是负担 |
| 弹出式通知（toast）成功提示 | 结果已经在眼前，不需要再通知一次 |
| 首次运行引导向导 | 直接可用，用空态文案代替向导 |
| 设置项超过 2 屏 | 设置越多说明决策越没做完，该定默认值 |
