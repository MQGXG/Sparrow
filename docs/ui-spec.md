# 界面规格（UI Spec）

> 界面只为「工具集合」服务：**同一套骨架，装不同的工具。** 工具不拥有界面，只贡献参数和结果。

---

## 一、三种入口，一套骨架

| 入口 | 唤出方式 | 用途 | 尺寸 |
|---|---|---|---|
| **命令面板** | `Ctrl + Alt + S` | 主力。搜工具 → 立即执行 | 640 × 420，居中偏上 |
| **工作区窗口** | 面板里选「打开工作区」 | 需要看大结果、调参数 | 1100 × 720 |
| **托盘菜单** | 右键托盘图标 | 最近工具、设置、退出 | 系统菜单 |

**M0 只做命令面板 + 托盘。** 工作区窗口 M1 再补。

理由：命令面板能验证 90% 的体验假设，工作区是「看结果更舒服」的增强，不是闭环前提。

---

## 二、命令面板（M0 唯一的主界面）

```text
┌──────────────────────────────────────────────────────┐
│  🔍  搜索工具、粘贴内容后回车…                        │  ← 输入框，自动聚焦
├──────────────────────────────────────────────────────┤
│  ▸ JSON 格式化                        格式化 · json   │  ← 选中项，Enter 执行
│    剪贴板历史                          历史 · 剪贴板  │
│    截图识别文字                          OCR · 截图    │
│    文本变形                             文本          │
├──────────────────────────────────────────────────────┤
│  ↑↓ 选择   Tab 补全   Enter 执行   Esc 关闭           │  ← 键盘提示，常驻
└──────────────────────────────────────────────────────┘
```

### 2.1 交互规则（这些是产品的核心，不是细节）

| 行为 | 规则 |
|---|---|
| **唤起** | 记起上次位置；若焦点窗口在另一块屏，则出现在那块屏（按该屏 DPI 缩放） |
| **输入即筛选** | 每次按键即时过滤，延迟 ≤ 50ms，不显示 loading |
| **排序** | `匹配度 × 权重 × 最近使用` 三者加权，不按字母序 |
| **空查询** | 显示最近使用的 5 个 + 固定工具，不是全部工具列表 |
| **粘贴后回车** | 输入框里的内容不是工具名时，按「输入形态」匹配工具（文本 → 文本类工具） |
| **Esc** | 有输入时清空；无输入时隐藏到托盘 |
| **失焦** | 隐藏到托盘（可设置关闭） |
| **执行中** | 面板不关，显示进度；完成后面板内直接出结果卡片 |

### 2.2 结果卡片（面板内，M0 起始）

```text
┌──────────────────────────────────────────────────────┐
│  JSON 格式化                                  12 ms  │
├──────────────────────────────────────────────────────┤
│  {                                                   │
│    "name": "sparrow",                                │
│    "version": 1                                      │
│  }                                                   │
├──────────────────────────────────────────────────────┤
│  [复制]  [保存]  [固定]  [发送到…]                    │
└──────────────────────────────────────────────────────┘
```

- 文本结果限高 6 行，超出滚动，不自动撑高面板。
- 图片结果限高 240px。
- 错误用红色左边框 + 一行说明，不带堆栈（堆栈进日志）。

## 三、工作区窗口（M1）

工具集合的正确形态是**一个工作区，装所有工具**，而不是「每个工具一个窗口」。

```text
┌─────────────────────────────────────────────────────────────┐
│  Sparrow                              [搜索 / 命令…]   ─ □ ×│
├──────────────┬──────────────────────────────┬───────────────┤
│ 工具          │ 输入                          │ 参数          │
│              │ ┌──────────────────────────┐ │               │
│ ▸ 剪贴板      │ │                          │ │ 模式  [格式化▾]│
│   JSON        │ │   （文本 / 图片 / 文件）   │ │ 缩进  [2      ▾]│
│   文本        │ │                          │ │               │
│   文件        │ └──────────────────────────┘ │ 最近结果      │
│   图片        │            ↓                 │ · 12:04 1.2KB │
│   OCR         │ 结果                          │ · 11:58 3.4KB │
│   SVG         │ ┌──────────────────────────┐ │               │
│   开发        │ │                          │ │ 收藏          │
│   AI          │ │                          │ │ · …           │
│              │ └──────────────────────────┘ │               │
├──────────────┴──────────────────────────────┴───────────────┤
│ 就绪 · 本地引擎          [复制] [保存] [固定] [发送到…]      │
└─────────────────────────────────────────────────────────────┘
```

**固定四区**：工具列表（左） / 输入+结果（中） / 参数+历史（右） / 动作条（底）。

工具的 UI 贡献**只有两处**：右上的参数面板（由 `Descriptor.Parameters` 自动生成）、中下的结果渲染（由 `Payload` 类型选择渲染器）。

### 3.1 渲染器映射

| Payload | 渲染器 |
|---|---|
| `TextPayload` | 等宽文本 + 语法高亮（AvaloniaEdit） |
| `SvgPayload` | SVG 渲染预览（Svg.Skia）+ 源码切换 |
| `ImagePayload` | 图片查看（缩放 / 适应宽度） |
| `FileSetPayload` | 文件列表 + 打开所在位置 |
| `TablePayload` | 表格（M2，先用 DataGrid 或自绘） |

**工具不能自定义渲染器。** 需要新的展示形态 = 新的 Payload 类型 = 一次架构变更，要慎重。

## 五、状态设计

每个工具都可能处于 5 种状态，界面必须都覆盖：

| 状态 | 表现 |
|---|---|
| **空态**（无输入） | 「粘贴或输入内容，再选一个工具」。不显示空白框 |
| **就绪**（有输入、未执行） | 输入已就位，参数显示默认值，动作条只有「执行」 |
| **执行中** | 进度条 + 取消按钮；超过 300ms 才显示进度（避免闪烁） |
| **成功** | 结果卡片 + 动作条全亮；耗时显示在标题右侧 |
| **失败** | 红色左边框 + 一句人话 + 「查看日志」链接 |
| **不可用** | 工具置灰，hover 显示原因（「当前平台不支持 OCR」/「未配置 AI」） |

「不可用」这一态最容易被忽略，但它是插件化工具集合的必需品。

## 六、键盘（第一优先级）

命令面板类产品，鼠标是备选。

| 键 | 行为 | 状态 |
|---|---|---|
| `↑` `↓` | 移动选中项（循环） | ✅ 已实现 |
| `Enter` | 执行选中工具 | ✅ 已实现 |
| `Ctrl + C` | 复制结果 | ✅ 已实现（隧道阶段拦截） |
| `Esc` | 关闭面板 | ✅ 已实现（"清空输入"待补） |
| `Tab` | 用当前选中项补全输入框 | ⬜ 未实现 |
| `Ctrl + Enter` | 执行并「发送到…」 | ⬜ 未实现 |
| `Ctrl + 1..9` | 直接执行第 N 项 | ⬜ 未实现 |
| `Ctrl + ,` | 打开设置 | ⬜ 未实现 |

**焦点规则**：面板打开即聚焦输入框。

### 6.1 中文输入法下的 Enter（实测踩到的坑）

中文输入法激活时，字母键和 Enter 都会被 Avalonia 标记为 `Key.ImeProcessed`：

```text
输入 j s o n   → TextBox 仍是空的（"json" 在 IME 组合缓冲区）
第一次 Enter   → IME 把 "json" 上屏 → 搜索框更新 → 列表过滤
第二次 Enter   → Key.Enter → 执行工具
```

**宿主规则：见到 `Key.ImeProcessed` 直接放行，绝不抢。**

如果抢了第一次 Enter，会发生：先执行工具 → 随后上屏触发搜索刷新 → 结果被清空。
用户看到的现象是"按了回车没反应"（其实执行过，只是结果被覆盖了）。

代价是中文输入法下要按两次 Enter。这是可接受的：第一次 Enter 本来就在做「确认输入」。
英文输入法或无 IME 时一次即可。

回归测试见 `tests/Sparrow.Tests/PaletteWindowTests.cs` 的 `ImeProcessed的Enter_不执行工具也不复制`。

### 6.2 为什么快捷键走隧道阶段

`TextBox` 会把 `Enter` 标成已处理、把 `Ctrl+C` 交给自己的复制命令。
冒泡阶段（包括 `handledEventsToo`）都拿不到，所以窗口在 `RoutingStrategies.Tunnel` 上先处理。

## 八、插件管理（设置里的一个页签）

工具都是插件，所以「管理工具」= 「管理插件」。只有一页，不做花活。

```text
┌─────────────────────────────────────────────────────────────┐
│ 设置 › 插件                                                  │
├─────────────────────────────────────────────────────────────┤
│  名称              版本     工具数   状态      操作          │
│  JSON 格式化       1.0.0     1       ● 启用    [禁用] [目录]  │
│  剪贴板历史        1.0.0     1       ● 启用    [禁用] [目录]  │
│  截图识别          1.0.0     2       ● 启用    [禁用] [目录]  │
│  图片描摹          0.9.0     1       ○ 禁用    [启用] [目录]  │
│  某第三方插件      0.1.0     1       ⚠ 异常    [重试] [目录]  │
├─────────────────────────────────────────────────────────────┤
│  [打开插件目录]   [重新扫描]                                  │
└─────────────────────────────────────────────────────────────┘
```

| 设计点 | 规则 |
|---|---|
| 不做「在线安装」 | `scope.md` 已明确不做插件市场。只能「打开目录」手动放 |
| 状态只有 4 种 | 启用 / 禁用 / 异常 / 不可用（能力不满足） |
| 异常可重试 | 不要求重启应用，重新加载该插件即可 |
| 显示工具数 | 提醒用户「一个插件可能提供多个工具」（OCR 就是 2 个） |
| 不显示内部路径 | 「打开目录」按钮代替展示路径，减少误操作 |
| 不提供「设置」入口 | 工具的参数在工具自己的参数区，不在插件管理页 |

**异常状态必须给原因**，一行小字：

```text
⚠ 异常   清单无效：plugin.json 第 4 行缺少 "entryAssembly"
⚠ 异常   版本不兼容：需要 SDK 2.x，当前 1.0
```

没有原因的灰显等于让用户猜，这比不显示更糟。

## 九、反模式（明确不做）

| 不做 | 原因 |
|---|---|
| 每个工具一个独立窗口 | 工具集合退化成「一堆小软件」 |
| 工具自定义 UI 布局 | 界面不可预测，加工具成本爆炸 |
| 动画 > 150ms | 高频工具，动画是负担 |
| 弹出式通知（toast）成功提示 | 结果已经在眼前，不需要再通知一次 |
| 首次运行引导向导 | 直接可用，用空态文案代替向导 |
| 设置项超过 2 屏 | 设置越多说明决策越没做完，该定默认值 |
