# 插件隔离与资源边界

日期：2026-11-28
状态：现状记录 + 待办清单

## 结论

- **类型 / 程序集层面隔离**：一个插件看不到另一个插件的类型和静态字段。
- **资源层面不隔离**：同一个进程、同一个 GC 堆、同一个线程池、同一个 UI 线程。
- 所以目标不是「一个插件不占资源」，而是：
  1. 一个插件**不能破坏**另一个插件的对象与状态；
  2. 一个插件**不能拖垮**整个宿主（有上限、有闸门、有回退）。

## 隔离矩阵

| 层 | 是否隔离 | 说明 |
|---|:--:|---|
| 程序集 / 类型 | ✅ | 每插件一个 `PluginLoadContext`（collectible） |
| 静态字段 | ✅ | 各自 ALC，互不可见 |
| 插件异常 | ✅ | `ToolRunner` 捕获后交给宿主，不向其他插件传播 |
| 契约面 | ✅ | 插件只能看到 `Sparrow.Plugin.Sdk` |
| 文件访问 | ⚠️ | `Files` 输入通过 `ScopedFileAccess` 限定在输入文件 |
| 内存 / GC 堆 | ❌ | 同进程；大分配会影响所有插件 |
| CPU / 线程池 | ❌ | 共享；长任务会挤占执行槽位 |
| UI 线程 | ❌ | 插件执行已移出 UI 线程；UI 视图仍会回到 UI 线程 |
| 网络 / 磁盘 / 句柄 | ❌ | 共享 |
| 原生崩溃 | ❌ | P/Invoke 段错误会带走整个进程 |

## 内存：谁在占，占多久

| 来源 | 位置 | 生命周期 |
|---|---|---|
| 插件程序集 | 插件 ALC | 卸载或进程退出 |
| 插件静态缓存 | 插件 ALC | 卸载或进程退出 |
| 执行时的临时分配 | 进程 GC 堆 | 正常 GC 回收 |
| 本地翻译模型 | **宿主**（`LocalTranslationService`） | 单次调用内 `using` 释放；静态 `Gate` 串行，避免同时加载两份 |
| OCR 模型 / 识别 | **独立 worker 进程** | worker 池空闲超时后回收 |
| 视频转码 | **ffmpeg 子进程** | 子进程退出 |
| 工具结果 | 宿主 `WorkspaceViewModel` / `PaletteViewModel` | 下一次结果或清空 |
| 历史记录 | 宿主 JSONL | 按条数 / 天数清理 |

关键判断：**长期占用通常来自宿主结果与历史，而不是插件代码。**

## 执行路径现状

- `ToolRunner.ExecuteAsync` 统一 `Task.Run`，同步插件不会卡 UI 线程
- 兜底超时 10 分钟，超时后放弃等待（后台工作无法强制终止）
- 取消通过 `CancellationToken` 传递
- 插件异常由 `ToolRunner` 向调用方抛出，工作区 / 面板各自捕获并显示错误

## 护栏（状态）

### 1. 结果上限（✅ P6 核心已完成）

在 `ToolRunner` 统一收口，超限时保留可读前缀并标记 `ToolResult.Notice`：

- 文本 / SVG / OCR：1,000,000 字符
- 表格：10,000 行、64 列
- 文件集：2,000 条路径
- 图片：32 MB（超限直接拒绝，保护内存）
- 历史落盘：单条输出再截断一次

表格 / 文件集的 `Notice` 上屏属于 P6-B。

### 2. 重任务闸门（待做）

- 同一时间只允许一个「重任务」（本地模型、OCR、视频）
- 轻任务（JSON、Base64、哈希）不受影响
- 需要一个显式的工具分类，不能按名字猜

### 3. worker 进程规则（待做）

| 类型 | 运行位置 |
|---|---|
| 纯计算 | 宿主进程，线程池 |
| 原生库 / 大模型 / 长任务 | 独立 worker 进程 |
| UI | 宿主进程，控件由宿主提供 |

### 4. 表面槽位（✅ P4 已完成）

```text
宿主外壳（返回 / 名称 / 复制 / 执行）
└─ 表面槽位 ContentControl
    ├─ 通用表面（Transform）
    ├─ UI SDK 组合（Session，嵌入）
    └─ 插件 Control（受信任，可嵌入或独立窗口）
```

- 插件视图创建失败 → 回退通用表面，记日志，不拖垮工具台
- 独立窗口只给「必须活过工作区」或「必须覆盖其他应用」的场景
- 窗口不是隔离边界；真隔离只有多进程

## 验收

- 超限结果有可见提示，历史文件不会无限增长
- 一个插件执行失败 / 超时 / 取消，不影响其他插件继续使用
- 带界面的插件禁用后提示「重启生效」
- 重任务同时只跑一个，轻任务不被阻塞
- 原生库相关插件不在宿主进程内直接执行
